# IDL online round: public site and adjudicator site

Two small Node services in one repo. Deploy each as its own Render web service.

| | Public site | Adjudicator site |
|---|---|---|
| For | students, parents, hosts | the ~30 adjudicators, hosts |
| Start command | `npm run start:public` | `npm run start:adj` |
| Shows | each student's 3 rounds (planned slot, then room and opponent once paired), room finder, all rooms for a section, projector mode | rooms per adjudicator per day, and a personal page with that adjudicator's debates and **Open ballot** buttons |
| Sheet reads | only when the host presses **Refresh** (and once at startup) | on demand, reused for 15 s |
| Holds secrets? | no tokens, no adjudicator data | `ADJ_SECRET`, ballot tokens |

Code layout: `shared/` (time rules, sheet reading, parsing), `public/`, `adj/`. In each service the server and `lib/` are the **data layer**; the `static/` folder (HTML, CSS, browser JS) is the **display layer**. To restyle, change the variables at the top of `public/static/app.css` or `adj/static/adj.css`.

## 1. Try it now (sample data, no Google needed)

```
npm install
npm run dev:public      # http://localhost:3000   host page: /host/devkey
npm run dev:adj         # http://localhost:3001   host links page: /links/devkey
npm test                # 37 tests
```

The sample files in `sample/data` are **fake**: pairings were generated by your real `Pairing.gs` on the slot plan, and adjudicators are "Sample Adjudicator NN". To test any moment of the event, add a fake IST clock to the URL:

- `http://localhost:3000/?now=2026-10-21T15:45` (a section is live)
- `http://localhost:3000/?mode=projector&now=2026-10-21T15:45`
- `http://localhost:3000/?now=2026-10-22T15:45` (Middle block with sides hidden)
- adjudicator page: `http://localhost:3001/links/devkey` lists personal links; add `&now=2026-10-21T16:35` to one

To test the host flow: edit `sample/data/Debates.csv` (for example change `FALSE` to `TRUE` in `sides_visible`), press **Refresh from sheet** on `/host/devkey`, and watch the public page update within a minute. `npm run sample` regenerates the sample pairings.

## 2. Connect the real sheet

1. **Tabs the code reads.** `Debates` (columns by header name, as written by Desk.gs), `Adj_Grid`, `Config`, and a slot-plan tab (default name `Roster`) with the headers `student_id, name, category, state, R1 date, R1 slot, R2 date, R2 slot, R3 date, R3 slot`. Your `IDL_slot_plan.xlsx` `Master_Schedule` tab has exactly these headers: paste it into the `Roster` tab, or add it as a tab and set `SLOT_TAB=Master_Schedule`. Dates without a year (`21 Oct`) use `EVENT_YEAR`. `UNPLACED` or blank means "Slot to be confirmed".
2. **Google service account (about 10 minutes).** Google Cloud Console > create a project > enable the *Google Sheets API* > IAM & Admin > Service Accounts > create one > Keys > Add key > JSON. Open the sheet > Share > add the service account's email as **Viewer**. Paste the JSON into `GOOGLE_CREDENTIALS`. Set `SHEET_ID` from the sheet URL.
3. **Run `Create secret` and `Generate debate tokens`** in the ballot app *before* the first pairing, so the tokens in `Debates!L` match what the ballot app checks. See `BALLOT_APP_PATCH.md`.

The public service asks Google only for the safe columns of `Debates` (it never requests `debate_id`, `token`, `adjudicator`, `key` or `time_made`). A test checks this.

## 3. Deploy on Render (one click)

1. Push this folder to a GitHub or GitLab repo (the repo root must contain `render.yaml` and `Dockerfile`).
2. Click **Deploy to Render**: open `https://render.com/deploy?repo=<YOUR_REPO_URL>` (replace the placeholder with your repo's URL; or Render dashboard > **New > Blueprint** > pick the repo).
3. Render reads `render.yaml` and creates **two** Starter web services, `idl-public` (with a 1 GB disk for the host switches) and `idl-adj`. Both build from the same `Dockerfile`; `dockerCommand` decides which one runs.
4. When asked, fill `SHEET_ID` and `GOOGLE_CREDENTIALS` for both services. `ADMIN_KEY` and `ADJ_SECRET` are generated for you. Leave `BALLOT_APP_URL` empty until you have it.
5. Open each service's **Logs**. The public one should print `Refreshed: N students, M debates`.
6. Find your private URLs: Render > service > Environment > `ADMIN_KEY`.
   - Host page: `https://<public-service>.onrender.com/host/<ADMIN_KEY>`
   - Adjudicator links: `https://<adj-service>.onrender.com/links/<ADMIN_KEY>`

Run locally in Docker with `docker build -t idl .` then `docker run -p 10000:10000 -e PORT=10000 -e SOURCE=google -e SHEET_ID=... -e GOOGLE_CREDENTIALS='...' idl` (add `node adj/server.js` at the end for the adjudicator site).

Keep both services at **one instance** (the data is held in memory). Do not use the free plan on the day: it sleeps after 15 minutes idle and takes about a minute to wake.

## 4. Running it

**Host page (public service, `/host/<ADMIN_KEY>`).** No password: the long random URL is the protection, so share it only with hosts (change `ADMIN_KEY` to rotate it).
- **Refresh from sheet** reads the sheet once and publishes. Do it after *Make pairings* and after *Reveal sides*. The page shows what it published and flags problems (a room used twice, a student in two debates, rounds planned out of date order, students with no slot).
- **Schedule** switch: off shows students "The schedule will be released soon" and the server sends no student data.
- **Pairings** switch: off shows planned slots only.
- **Roster tab** switch: on adds a public "Roster" tab listing every student with name, ID, state and all 3 rounds (date, time, and room/opponent once paired). State is only sent to browsers while this switch is on. Off by default.
- If Google fails, the refresh says so and the public page keeps the last good data.

**Public page.** Students need no login. The page checks a tiny version endpoint every 45 s and downloads new data only after you refresh. It shows "Checked at hh:mm:ss" and a warning if the server cannot be reached for 2 minutes. Times use the server's clock, so a phone with the wrong time still shows the right "now".

**Adjudicators.** Open `/links/<ADMIN_KEY>`, copy each person's link (or download the CSV) and send it to them. A link is `/?adj=<name>&t=<code>`; the code is derived from the name and `ADJ_SECRET`. Renaming someone in `Adj_Grid` changes their link; changing `ADJ_SECRET` changes everyone's. Without a valid link the person sees only the room allocation table (names and rooms, no students, no ballot links).

## 5. Privacy and security

- Public data: student ID, name, category (state only if `SHOW_STATE=true`), planned slots, and for paired debates the date, block, section, room, round, the two students and, when revealed, the sides. Nothing else exists in the page's data: no email, phone, school, token, ballot link or adjudicator name.
- **Sides.** Where `sides_visible` is FALSE the server sends the two students in alphabetical order with no side field. Sorting and column order carry no hint.
- **Trade-off:** the public page downloads the whole name list so search is instant on slow phones and 500 viewers cost the sheet nothing. Anyone can therefore read the full list of names and IDs. Pages are marked `noindex` and send no referrer.
- The Google service account can read the whole workbook (Google shares per spreadsheet, not per column). The public service only requests the safe columns, but the key itself is powerful: keep it only in Render environment variables, never in the repo.
- Walkovers show the absent student's name as absent, as requested. Change the wording in `public/static/app.js` if you prefer something softer.

## 6. What could go wrong on the day

| Problem | What happens | What to do |
|---|---|---|
| Google is slow or down when you press Refresh | The refresh reports the error; the public page keeps the last good data | Press again. The page footer shows when data is from |
| You forget to press Refresh after pairing | Students still see "announced at check-in" | Set `AUTO_REFRESH_SECONDS=60` if you would rather not rely on the button |
| A pairing is dissolved or changed | Students see the old pairing until the next refresh; unstarted pairings are labelled as changeable | Refresh after any change |
| Sides revealed on the call but not in the sheet | The page keeps hiding them | Reveal in the sheet, then Refresh |
| Render restarts mid-event | The service re-reads the sheet at startup; switches come back from the disk | Check the host page shows a recent "Last refreshed" |
| Render free plan used by mistake | First visit after idle takes about a minute | Use Starter on the day |
| 500 students open the page at once | Data is served from memory; the sheet is not touched by viewers | Nothing |
| A student's phone clock is wrong | "Now" and "Next" use the server clock | Nothing |
| A student is not found | Names are matched loosely; IDs are exact | Search by ID; check the roster spelling |
| Two students share a name | Results list ID and category for each | Ask for the ID |
| Roster has rounds out of date order | Shown as planned; the host page warns | Fix the plan before publishing |
| Adjudicator changed in `Adj_Grid` after pairing | The page falls back to the grid when `Debates.adjudicator` is blank and warns on a mismatch | Fix whichever is wrong and refresh the adjudicator page |
| Ballot button says "not ready" | The debate has no token | Run *Generate debate tokens* in the ballot app |
| Ballot button says "not set up yet" | `BALLOT_APP_URL` is empty | Set it on the adjudicator service and redeploy |
| An adjudicator link leaks | Anyone with it can see that adjudicator's debates and ballot buttons | Rename the person in `Adj_Grid` (new link), or rotate `ADJ_SECRET` and resend all |
| Host link leaks | Anyone could press Refresh or switch the schedule off | Change `ADMIN_KEY` in Render |

## 7. Assumptions to check

- One name per `Adj_Grid` cell, or several separated by commas, semicolons or new lines.
- Walkovers have no ballot button (the present student keeps the round).
- Section time = block start + (section − 1) × 20 minutes; the number of sections comes from `Config` (the 5:30 to 6:00 PM block has 1).
- At full size (2,500 students, 4,000 debates) the public data is roughly 75 KB compressed.
